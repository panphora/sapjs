Building malleable document apps with sapjs

This guide is for a developer or an LLM building an app that lives in one HTML file: a tracker, a Kanban board, a notes list, a CRM. It says how to build such an app with sapjs well: where each piece of data goes, which sapjs features to reach for, and the traps. The attribute reference is llms.txt. ClayJS, which saves the file, syncs it between tabs and gives it an edit mode, has its own complete guide. Read this one first for the app, and the ClayJS guide for saving, sync and editing.

Every worked app in section 9 runs in the sapjs test suite against the engine, so the code here is code that works.

#1. The one rule

The saved DOM is the data. A malleable document app has no database and no JSON blob. Its records are elements in the file, its fields are attributes and text on those elements, and saving the page saves the app. sapjs adds the reactive part: it reads the page, computes what you declare, and paints the results back into the page.

Three consequences shape every decision below:

  • Store a record once. One element per record, in one place. A second copy (a JSON mirror, a rendered duplicate) drifts the first time a merge or a hand edit touches one of them.
  • Everything else is derived. Counts, totals, filtered lists, the open card's editor: compute them from the records on every pass, never store them as data.
  • Per-tab state is not data. The search box, which card is open, which tab is selected: none of it belongs in the saved file.

sapjs is built for this. It keeps no state of its own between passes: every change rebuilds the whole state tree by reading the live page, so a live-sync merge, an undo, a devtools edit and a keystroke are all the same thing, input to the next pass.

#2. When to use sapjs

Use sapjs for:

  • totals, counts, averages and anything else computed from records;
  • lists that are sorted, filtered or grouped views of records;
  • forms that add records, and editors that change the selected record;
  • show and hide rules, classes and attributes that depend on data.

Write plain JavaScript (a Sap(el) call in a handler, or a small script) for:

  • talking to the network, files or the clipboard;
  • drawing on a canvas, or anything that needs a library;
  • one-off commands such as an import.

A good sapjs app has one <main sap> with no app code in it, plus a short script for those few commands. When an app grows a large render function, that is a sign a record field or an each= view was missed.

#3. The skeleton

With ClayJS (saving, sync, edit mode):

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Expenses</title>
  <style>
    [item][template] { display: none }
  </style>
</head>
<body>
  <main id="app" sap>
    …
  </main>
  <script src="https://clayjs.com/v1/clay.js?plugins=sync,sortable,undo,indicator&exclude=richclay"></script>
  <script src="https://clayjs.com/v1/sap.js"></script>
</body>
</html>

Standalone, without saving: replace both script tags with <script src="https://cdn.jsdelivr.net/npm/@panphora/sapjs@0.5/dist/sap.min.js"></script>.

  • Hide template rows in your own CSS. sapjs adds the same rule at runtime, but the file renders before scripts run.
  • Every [sap] root mounts by itself. There is no init call.
  • Check it worked: the console prints one sap ✓ line per app, Sap.status().ok is true, and no element carries sap-error. A sap ✗ line names the element and the fix.

#4. Designing records

A record is one element with item, inside a container with items="name". Its fields are:

Field kind Declare it Read it as Saved as
Text the user edits in place bind on an input, textarea or text leaf inside the record item.title the control's value or text
A value with no visible control state="data-due" on the record item.due data-due="2026-10-20"
A number state="data-points:num" item.points data-points="3"
A yes/no flag CSS selects on state="data-done:presence" item.done data-done present or absent
A yes/no value CSS compares state="data-flag:bool" item.flag data-flag="true" or "false"
A nested list items="checks" on a child container item.checks child [item] elements 
<ol items="cards">
  <li item data-id="c-brief" state="data-due data-done:presence" data-due="2026-10-20">
    <span bind="title">Write the brief</span>
  </li>
</ol>

Rules that keep records healthy:

  • Give every record a data-id. It is the record's $key, and live sync pairs elements across tabs by it. Write data-id="" on the template row; $add mints a fresh one for each new record, and fresh ids for every id and data-id inside it.
  • Prefer data-* attributes for fields without a control. They never collide with HTML's own attribute names, and item.due reads data-due the way el.dataset does.
  • Use :presence for flags. [data-done] selectors and hasAttribute then mean what they say. :bool writes the word "false", which a presence selector still matches.
  • Field names are lowercase identifiers. HTML lowercases attribute names, and a hyphen in a name parses as subtraction, so due-date is a mount error. data-due-date is fine: it reads as item.dueDate.
  • Put persist on bound inputs in records when the app runs on ClayJS, so a typed value is written into the attribute the save captures.

#Nested lists and shared blueprints

A list can hold lists: lists hold cards, cards hold checklist items. Each nested list needs a blueprint to add from. Rather than repeating an [item template] row in every copy, write one shared blueprint anywhere in the app:

<template items="checks">
  <li item data-id="" state="data-done:presence"><span bind="label">New item</span></li>
</template>

Every items="checks" list without its own template row clones from it, including lists that sit inside other blueprints.

#5. Views are projections

The records are the data. What the user looks at is often a view of them: the cards due this week, the notes matching a search, a card's checklist inside its editor. Build views with each=:

<ul each="state.cards.filter(c => !c.done).sort((a, b) => a.due.localeCompare(b.due))">
  <template>
    <li><input type="checkbox" bind="done"> <span text="item.title"></span></li>
  </template>
</ul>
  • One row per array element, matched by key= (default item.$key), so rows are reused and moved, never rebuilt. Focus and scroll survive.
  • View rows carry clay="editor-ui": they are never saved and never synced. Each tab draws its own.
  • A row that stands for a record edits that record. In the example, bind="done" reads the card's data-done and writes it back. The rule is the same for bind and set:: a field the record owns goes to the record; anything else goes to the scope the list is drawn in. A bind that matches neither is error E43 and writes nothing.
  • trigger-remove in a row removes the record, and Sap(el) in a row returns the record's proxy.
  • calc: does not run inside view rows. Compute on the record, or in the each= expression.

Filter with views, not by hiding records. show= on a saved record writes hidden into it, and under ClayJS that saves and syncs. Filter in the each= expression instead. If the records themselves are the visible list (a board you drag cards on), hide non-matching ones with a stylesheet painted inside a clay="freeze" element (ClayJS guide 8.11), so the hiding rule is per tab.

Keep the records the main surface when the user edits structure. Dragging cards between lists, rich text and in-place editing all act on the elements they touch. View rows are not saved, so a drag inside a view moves nothing. Make the records themselves the board or the table, and use views for everything secondary.

#6. Three kinds of state

Kind Example Where it lives
Data a card's title, an expense amount record fields (section 4)
Per-tab the search text, the open card, the active tab transient fields, or the URL hash
Derived totals, counts, the filtered list calc:, paints and each=

Per-tab state is declared transient: it drives the app and is never written into the file.

<main sap state="q:transient open:transient tab:transient=board">
  <input type="search" bind="q" transient>

transient on a bound control keeps its value out of the file too. A field that should survive a reload or be shareable as a link belongs in the URL hash instead (clay-router, section 8).

Derived values are paints:

<output calc:total="sum(state.expenses, 'amount')" text:usd2="state.total">$54.50</output>
<span text="count(item.checks, c => c.done) + '/' + item.checks.length">1/2</span>

Paint the computed values into the file. When the saved file already shows $54.50, the first pass changes nothing, and sapjs reports mount writes 0. A mismatch is not an error, but under ClayJS a write at load is an edit. A paint that is the same in every tab (a total, a count) is ordinary saved content. A paint that differs per tab (anything from today's date, the locale, the search box) goes in a clay="freeze" element, so each tab fills its own copy and nothing saves or syncs.

#7. Detail views

An app usually needs a place to edit one record in full. There are two good shapes.

The record is the modal (ClayJS apps with rich detail). Keep the detail fields inside the record element, hidden on the face by CSS, and show the record itself as an overlay when it is open. Open state is the URL hash: route="card" on the list, clay.route.set({ card: id }) to open, and CSS on [route-active]. Nothing is copied, a peer's edit to the open card appears in place, rich-text toolbars work, and Back closes it. This is how the starter Kanban template works, and ClayJS guide 9.5 covers it.

A detail= editor (plain fields, any number of panels). detail="LIST by KEY" projects one record into a panel or a dialog. Controls inside are painted from the record and write through to it:

<main sap state="open:transient">
  …
  <div clay="freeze">
    <dialog detail="lists.cards by state.open">
      <input bind="title">
      <form method="dialog"><button>Close</button></form>
    </dialog>
  </div>
</main>
  • The path walks through nested lists: lists.cards finds a card in any list.
  • On a <dialog>, sapjs calls showModal() when a record matches and close() when none does. A user close clears a plain state.NAME key, so the next click on the same record opens it again.
  • Wrap the dialog in clay="freeze" so the open attribute that showModal() writes is never saved (W31 warns otherwise). Not clay="editor-ui": that removes the dialog from the file.
  • Make the key transient, or a saved selection reopens the dialog for every visitor and opens it in every peer's tab.
  • An each= inside the editor shows the record's nested list, and its rows edit those nested records. A <form trigger-add> inside the editor adds to the open record's list.
  • A <div> or <aside> with detail= toggles hidden instead: use it for a side panel.

Pick the record-as-modal shape when the detail holds rich text, needs a shareable link, or is the main editing surface. Pick detail= when the fields are plain controls, or the same record is edited in two places at once.

#8. Working with ClayJS

sapjs and ClayJS were built for each other. What happens without any code:

  • sapjs rides the ClayJS mutation hub, so its paints never trigger an autosave or a dirty mark by themselves.
  • A live-sync merge, an undo and a redo each re-derive the whole app.
  • A route change (clay:route) re-derives too, so expressions may read the hash.

What you do:

  • persist on bound inputs in records, so typed values reach the saved attributes.
  • Re-sync inputs after undo. sapjs reads a control's live value, and undo restores the attribute, not the live value. ClayJS guide 5.3 has the syncControls snippet to call on undo and redo.
  • Freeze per-tab paints and editors (sections 6 and 7).
  • Regions stack. View rows are editor-ui already. An editor dialog goes in freeze. Chrome you create at runtime goes in editor-ui, cloned from an unmarked <template>.
  • Edit-mode-only controls: show-when:editmode="true" shows an element only to the owner.
  • Reading the route: detail="lists.cards by (clay.route ? clay.route.get().card : '')" keys an editor on the hash. A user close does not clear a key like that, so close it yourself: onclose="clay.route.set({ card: null })" on the dialog.

#9. Worked apps

Each app below is a complete <main sap>, written with its computed values already painted, so it mounts with zero writes. Wrap it in the skeleton from section 3.

#9.1 Expense tracker

Records in a table, a form that adds them, and totals.

<main id="app" sap>
  <form trigger-add="expenses">
    <input bind="what" placeholder="What" required>
    <input type="number" step="0.01" bind="amount" placeholder="0.00" required>
    <select bind="category"><option>food</option><option>travel</option><option>other</option></select>
    <button>Add</button>
  </form>
  <table>
    <tbody items="expenses">
      <tr item template data-id="" state="data-category">
        <td><input bind="what" persist></td>
        <td><input type="number" step="0.01" bind="amount" persist></td>
        <td text="item.category"></td>
        <td><button trigger-remove confirm="Delete this expense?">×</button></td>
      </tr>
      <tr item data-id="e-groc" state="data-category" data-category="food">
        <td><input bind="what" persist value="Groceries"></td>
        <td><input type="number" step="0.01" bind="amount" persist value="42.5"></td>
        <td text="item.category">food</td>
        <td><button trigger-remove confirm="Delete this expense?">×</button></td>
      </tr>
      <tr item data-id="e-train" state="data-category" data-category="travel">
        <td><input bind="what" persist value="Train"></td>
        <td><input type="number" step="0.01" bind="amount" persist value="12"></td>
        <td text="item.category">travel</td>
        <td><button trigger-remove confirm="Delete this expense?">×</button></td>
      </tr>
    </tbody>
  </table>
  <p>
    Total <output id="total" calc:total="sum(state.expenses, 'amount')" text:usd2="state.total">$54.50</output>,
    food <output id="food" text:usd2="sum(state.expenses.filter(e => e.category === 'food'), 'amount')">$42.50</output>
  </p>
</main>
  • The form is a composer: on submit it clones the template and copies each of its controls into the new record's field of the same name, including the data-category field the record declares. Then it clears itself and refocuses the first field.
  • amount is a number because its input is type="number".
  • confirm= asks before deleting (clay.confirm under ClayJS, window.confirm alone).

#9.2 Kanban board

Lists of cards, a checklist per card, shared blueprints, and a card editor in a dialog.

<main id="board" sap state="open:transient">
  <section items="lists">
    <div class="list" item data-id="l-todo">
      <h2 bind="name">To do</h2>
      <ol class="cards" items="cards" sortable="cards">
        <li class="card" item data-id="c-brief" state="data-title" data-title="Write the brief" set:open="item.$key">
          <span text="item.title">Write the brief</span>
          <small text="count(item.checks, c => c.done) + '/' + item.checks.length">1/2</small>
          <ul class="checks" hidden items="checks">
            <li item data-id="k-outline" state="data-label data-done:presence" data-label="Outline" data-done></li>
            <li item data-id="k-draft" state="data-label data-done:presence" data-label="Draft"></li>
          </ul>
        </li>
      </ol>
      <button class="add-card" trigger-add="cards">+ Add a card</button>
    </div>
    <div class="list" item data-id="l-done">
      <h2 bind="name">Done</h2>
      <ol class="cards" items="cards" sortable="cards"></ol>
      <button class="add-card" trigger-add="cards">+ Add a card</button>
    </div>
  </section>

  <template items="cards">
    <li class="card" item data-id="" state="data-title" data-title="New card" set:open="item.$key">
      <span text="item.title">New card</span>
      <small text="count(item.checks, c => c.done) + '/' + item.checks.length">0/0</small>
      <ul class="checks" hidden items="checks"></ul>
    </li>
  </template>
  <template items="checks">
    <li item data-id="" state="data-label data-done:presence"></li>
  </template>

  <div clay="freeze">
    <dialog detail="lists.cards by state.open">
      <input class="title" bind="title">
      <ul each="item.checks">
        <template><li><input type="checkbox" bind="done"> <input class="label" bind="label"></li></template>
      </ul>
      <form trigger-add="checks"><input class="new-check" bind="label" placeholder="Add an item"></form>
      <form method="dialog"><button>Close</button></form>
    </dialog>
  </div>
</main>
  • The lists and cards are the records and the visible board, so a sortable drag moves the real elements.
  • Each card keeps its checklist inside itself (hidden, saved), so a card carries all its data when dragged or synced.
  • Clicking a card sets the transient open key; the dialog opens on the card in whichever list holds it.
  • Inside the dialog, bind="title" writes the card's data-title. The checklist is an each= view of the card's checks, and its rows edit those records: ticking a box adds or removes that item's data-done. The composer form adds a checklist item to the open card from the shared blueprint.

#9.3 Notes

A searchable, sorted list of notes, and an editor for the selected one.

<main id="notes" sap state="q:transient open:transient">
  <input id="q" type="search" bind="q" transient placeholder="Search">
  <button id="new" onclick="const s = Sap(this); s.open = s.$add('notes').$key">New note</button>

  <section items="notes" hidden>
    <article item template data-id=""><h3 bind="title">Untitled</h3><div bind="body"></div></article>
    <article item data-id="n-ideas"><h3 bind="title">Ideas</h3><div bind="body">A board for recipes</div></article>
    <article item data-id="n-books"><h3 bind="title">Books</h3><div bind="body">Read the ClayJS guide</div></article>
  </section>

  <nav id="list" each="state.notes.filter(n => (n.title + ' ' + n.body).toLowerCase().includes(state.q.toLowerCase())).sort((a, b) => a.title.localeCompare(b.title))">
    <template><a set:open="item.$key" class:on="state.open === item.$key" text="item.title"></a></template>
  </nav>

  <article id="editor" detail="notes by state.open" hidden>
    <input bind="title">
    <textarea bind="body"></textarea>
    <button trigger-remove confirm="Delete this note?">Delete</button>
  </article>
</main>
  • The notes are saved, hidden records. The visible list is an each= view, filtered and sorted in its expression, so searching never writes to a record.
  • The editor is a detail= panel. Typing writes through to the selected note, and its trigger-remove deletes that note.
  • "New note" uses Sap(el) from a handler: $add returns the new record's proxy, and its $key opens it.

#10. Checklist and traps

Before calling an app done:

  • The console shows sap ✓ for every app, and Sap.status().ok is true.
  • Sap.status().apps[0].mountWrites is 0 on a saved file (computed values are painted into the file).
  • Every record has a data-id, and every template row has data-id="".
  • Search text, open record and active tab are transient or in the hash.
  • No show= on saved records; views filter in each=.
  • A <dialog detail> sits inside clay="freeze" with a transient key.
  • Bound inputs in records carry persist (ClayJS apps).
  • Every app code path still works after an undo and after a peer's edit.

Traps, with the fix:

Symptom Cause Fix
state= has no effect it sits on an element that is not a scope (sap, scope=, [item], [detail]) move it to the record or add scope=
a field named due-date halts with E08 the hyphen parses as subtraction data-due-date, read as item.dueDate
a flag reads true after unticking :bool wrote "false" and CSS selects by presence declare it :presence
E43 on a bind in a view row the field is neither the record's nor the drawn scope's declare it on the record, or state= where the list is drawn
typing in a view row changes nothing in the file the row's field is per-tab expected; declare the field on the record to save it
a filter makes the file dirty show= on saved records filter in an each= view
the editor dialog opens for every visitor the key is saved make it transient
the dialog is missing after a save it was inside clay="editor-ui" use clay="freeze"
a value painted after a write is stale passes are batched Sap.refresh() before reading
a total keeps an undone number undo restored the attribute, not the input's live value syncControls on undo (ClayJS guide 5.3)
expressions fail under a strict CSP expressions compile with new Function allow unsafe-eval, or skip sapjs
